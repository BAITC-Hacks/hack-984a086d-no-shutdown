# Как обучать и настраивать модель

Здесь обучается регрессор нормализованной мощности для каждой турбины. Он получает ветер, температуру и циклические признаки времени. Текстовый чат — отдельный интерфейс; обучение этого регрессора не обучает языковую модель.

## Что уже сделано

- Исходные CSV сохранены. Пропуски не заполняются нулями или будущими наблюдениями.
- Десятиминутные значения агрегируются в почасовые средние. По умолчанию используются только 6/6 корректных измерений в час.
- Сравниваются исходный HistGradientBoostingRegressor, средняя кривая ветра, медианная кривая с шагом 0,25 м/с и три варианта градиентного бустинга с absolute_error: сглаженный, более подробный и использующий только ветер/температуру.
- Выбор идёт по среднему MAE трёх последовательных окон: июль–август, сентябрь–октябрь и ноябрь–декабрь 2025. Каждый раз модель обучается заново только на более ранних данных.
- Январь 2026 оставлен для финальной проверки; выбор гиперпараметров на нём не выполняется. После проверки рабочая модель обучается на всех данных до 1 февраля.
- Значения метрик, количество часов и хеши находятся в `artifacts/metadata.json`; читаемый отчёт — `reports/training_report.md`.

Более сложная модель не обязательно выигрывает. В рабочие артефакты попадает победитель валидации отдельно для каждой турбины. Сравнение с исходным HGB выполнено на тех же часах и границах, поэтому оно сопоставимо. Старые метрики демо на другом разбиении с новыми сравнивать нельзя.

## Повторить обучение

В активированном окружении проекта:

```sh
python -m windagent train --cutoff 2026-02-01T00:00:00+05:00 --timezone Asia/Almaty --timestamp-semantics start --min-samples 6
```

Команда записывает `artifacts/turbine_1.joblib`, `artifacts/turbine_2.joblib`, метаданные и отчёты. Она переобучает модели явно; кнопка пересчёта на сайте выполняет прогноз уже обученной моделью.

## Менять гиперпараметры

Скопируйте `config/training.example.json`. Например, для одного экспериментального кандидата:

```json
{
  "candidates": ["hist_gradient_boosting", "hgb_mae_smooth", "wind_median_curve"],
  "overrides": {
    "hgb_mae_smooth": {
      "max_iter": 320,
      "learning_rate": 0.04,
      "max_leaf_nodes": 15,
      "min_samples_leaf": 80,
      "l2_regularization": 3.0
    }
  }
}
```

```sh
python -m windagent train --config config/training.example.json --artifact-dir experiments/run-01/artifacts
```

| Параметр | Что меняет | Разумные значения для проверки |
|---|---|---|
| `loss` | Целевая ошибка обучения | `absolute_error` для MAE; `squared_error` для RMSE |
| `learning_rate` | Шаг обучения | 0.03–0.1; маленький шаг требует больше итераций |
| `max_iter` | Количество деревьев | 150–500 |
| `max_leaf_nodes` | Сложность каждого дерева | 7–31 |
| `min_samples_leaf` | Минимум примеров в листе | 30–100; больше — более гладкая модель |
| `l2_regularization` | Сглаживание листьев | 0–5 |
| `random_state` | Воспроизводимость | Оставить 17 для сопоставимых запусков |

Формат конфигурации проверяется; неизвестное имя модели или параметра приводит к ошибке. Признаки, число кандидатов и гиперпараметры меняйте по старым валидационным периодам. Не выбирайте следующую настройку по январской ошибке: после такого выбора январь перестаёт быть независимым тестом. Для нового этапа исследований нужен другой нетронутый период.

`--validation-months 6 --folds 3` меняют количество и длину валидационных окон. Число месяцев должно делиться на число окон. `--holdout-start` принимает точный ISO timestamp с часовым поясом; при отсутствии используется начало предыдущего календарного месяца перед cutoff.

## Что спросить у организаторов перед финальным обучением

1. Часовой пояс и менялись ли настройки часов в 2024 году. `Asia/Almaty` учитывает исторический переход UTC+6 → UTC+5; неоднозначные локальные timestamps исключаются и считаются в отчёте. Это предположение о CSV, а не установленный факт.
2. Timestamp означает начало или конец интервала? По умолчанию `start`. Если конец, используйте `--timestamp-semantics end`: до почасовой агрегации время смещается на 10 минут назад.
3. Какая задержка поступления телеметрии? Сейчас час считается доступным в момент завершения часа. При задержке её нужно добавить к `available_at` и заново проверить срезы.
4. Формула нормализации, номинальная мощность, высота измерения ветра и высота ступицы. Диапазон 0–1 не доказывает деление мощности на номинальную.

`--min-samples 4` допускает неполные часы, но меняет обучающую выборку и смысл её качества. Для защиты проекта сохранён строгий вариант 6/6. Пропущенный час не становится нулевой выработкой. Конфликтующие дубликаты времени требуют исправления исходных данных, а не выбора случайной строки.

## Что сильнее всего влияет на реальную точность

Отчёт обучения использует **фактический** ветер. Он оценивает зависимость мощности от погоды, но не точность прогноза будущего ветра. Нельзя назвать `1 − MAE` «точностью ИИ» или представлять условный MAE как ошибку прогноза на 48 часов.

Основной следующий эксперимент — получить подтверждённые оперативные архивы погоды до января 2026, сопоставить прогнозный ветер с SCADA на тех же целевых часах и обучить коррекцию смещения **только на более ранних выпусках**. Для проверки отдельно оценивать горизонты 0–23 и 24–47 часов, сравнивать с персистентностью, хранить момент публикации и лаг. На текущих cached ECMWF hindcasts историческая публикация не доказана; это показывается в интерфейсе и отчётах.

Данные февраля отсутствуют. Поэтому здесь нет измеренной февральской ошибки и обещания «максимально возможной точности». Достигнут измеренный выбор среди явно перечисленных кандидатов. Для прогноза ограничений мощности/остановок дополнительно нужны данные о доступности турбин, curtailment и состоянии оборудования.

Полоса на графике — условный исторический разброс ошибки регрессора. Она не покрывает всю неопределённость погоды и не гарантирует 90% попаданий будущих наблюдений.

## Проверки

```sh
python -m unittest discover -s tests -p test_training_protocol.py -v
python -m pytest -q
```

Проверяются: недопустимые дубликаты, агрегация начала/конца интервала, полнота часа, отсутствие тренировочных часов после cutoff и невозможность выбрать модель по финальному holdout.

# Текущий прогноз: Live

Режим Live получает текущий прогноз погоды и передаёт его уже обученным моделям
`conditional-power-v2`. Он отделён от реконструкции февраля. Исторический агент,
его данные, метрики и обученные артефакты сохранены.

## Откуда берётся погода

Используется [Open-Meteo Forecast API](https://open-meteo.com/en/docs) с явно
указанным `models=ecmwf_ifs`, UTC, ветром в м/с и температурой в °C. В почасовой
ряд входят `wind_speed_100m` и `temperature_2m`; блок current дополнительно
содержит `wind_speed_10m`. Официальная документация допускает почасовые переменные
в current, включая ветер 100 м. Current — оценка погодной модели, а не измерение
турбины. [ECMWF API](https://open-meteo.com/en/docs/ecmwf-api) описывает доступный
ветер на высотах 10/100 м и почасовой временной ряд.

`retrieved_at` — время фактического получения ответа. Идентификатор запуска
погодной модели не возвращается этим endpoint: `initialization_time=null`.
Нельзя выдавать retrieved_at за время инициализации или публикации запуска.
Live API нельзя использовать для исторического backtest февраля.

Показываются 24 или 48 полных часов, начиная **со следующего полного часа UTC**.
Например, при запросе 10:30 UTC первый час — 11:00–12:00. Даже ровно в 10:00
первый прогнозируемый интервал начинается в 11:00. Текущий незавершённый час
не включён. forecast_end — конец последнего интервала, не последняя метка ряда.

## Проверки и пересчёт

- Кэш действителен максимум 300 секунд. Проверяются реальный возраст получения,
  схема, параметры запроса, координаты, модель, единицы и контрольные суммы.
  Устаревшие JSON из импортированного архива не считаются свежим Live.
- Проверяются полные горизонты без дубликатов, UTC, конечные числа,
  неотрицательный ветер и широкие диапазоны правдоподобия: 0–100 м/с и −90…70 °C.
  Это проверка повреждённых входов, а не паспортные пределы турбины.
- Current должен быть не старше часа и не более чем на 15 минут впереди часов
  проверки. Будущее retrieved_at отклоняется даже при поддельном cache age=0.
- Временные ошибки провайдера повторяются до трёх раз с паузами. Если свежих
  данных нет, возвращается ошибка; старый архив или mock не подставляется.
- При пересечении часовой границы во время получения/расчёта выполняется один
  повтор для нового горизонта. Повторное пересечение заканчивается явной ошибкой.
- Refresh запрашивает погоду заново. Если погодные значения/источник и модель
  не изменились, используются прежние предсказания с новым checked_at и прежним
  issued_at. Изменение входов запускает модель снова. Служебное generationtime_ms
  не создаёт ложное изменение погоды.
- Хеши артефактов и конфигурации проверяются до и после вычисления. Изменение
  модели в середине запуска отклоняет результат. Ошибки и успешные результаты
  сохраняются в SQLite; текущие входы сохраняются вместе с результатом.

## Почему по умолчанию нет МВт и МВт·ч

В импортированном архиве есть число **2,5 МВт**, но нет подтверждённой формулы
нормализации мощности. В `config/turbines.json` число сохранено как
неподтверждённая настройка. По умолчанию выдаётся **нормализованная мощность**, а
`power_mw`, `energy_mwh`, `lower_mw`, `upper_mw` и энергетическая сводка равны null.
Среднее двух нормализованных рядов ВЭС — только равновесный показатель, не МВт.

Перевод включается только после подтверждения обоих условий организаторами:

```json
{
  "capacity_mw": 2.5,
  "capacity_verified": true,
  "capacity_evidence": "Ссылка или реквизиты подтверждения мощности",
  "power_normalization": "rated_capacity_fraction",
  "power_normalization_evidence": "Подтверждение: значение CSV = мощность / номинальная мощность"
}
```

Это пример структуры, **не подтверждение**, что 2,5 МВт верно. Не включайте эти
поля для min-max или неизвестной нормализации. При разрешённом переводе каждый
интервал длится один час: energy_mwh = power_mw × 1 ч. В текущей конфигурации
номинал общий для двух турбин; для разных номиналов потребуется изменить схему.

## Сценарий физической кривой

Импортированные пороги 2,5 / 10,5 / 25 м/с сохранены в отдельном
`windagent/physics.py` как **предположение для сценария**. По умолчанию
`physics_scenario.enabled=false`; обученная модель не обнуляется при ветре ниже
2,5 м/с. Ветер модели на 100 м не доказанно совпадает с ветром у ротора.

При явном включении сценария обнуляются значения ниже cut-in и выше cut-out;
исходные предсказания остаются в `raw_normalized_power` и исходных границах.
Счётчик изменений и предупреждение включены в ответ. Метрики исходной ML-модели
не описывают изменённые предсказания. Независимая проверка в
`docs/DATA_MODEL_AUDIT.md` показала ухудшение условного MAE от принудительного
обнуления; включение не является способом гарантированно повысить точность.

## API-контракт ядра

```python
from pathlib import Path
from windagent.live import LiveForecastAgent
agent = LiveForecastAgent(Path('.'))
result = agent.run(horizon=48, refresh=False)
status = agent.status()
```

`result` содержит mode=live, issued_at, checked_at, forecast_start, forecast_end,
model, capacity, warnings, farm, summary и turbines (список двух турбин).
Каждая турбина содержит current, provenance и points. Всегда доступны
normalized_power, lower_normalized, upper_normalized, wind_speed и temperature.
Для отображения используйте сохранённые points: повторный запрос погоды после
расчёта может вернуть другие значения.

Модель предупреждает о данных обучения старше 180 дней и погодных признаках
за пределами обучающего диапазона. Это сигналы для проверки, а не оценка точности.
Модель обучена до февраля; качество на текущую дату не измерено. Интервалы
не включают ошибку погодного прогноза, а неизвестные timezone и смысл временных
меток исходных CSV остаются ограничениями обучения.

## Проверка без сети

```bash
python scripts/verify_live.py
```

В текущем запуске прошли 13 unittest-проверок, а реальные обученные артефакты
проверены на детерминированном погодном fixture. Результат сохранён в
`reports/live_verification.json`. Реальный запрос Live API здесь не выполнялся;
успешный текущий прогноз внешнего сервиса не заявляется. Для пользовательского
запуска Live требуется интернет; обработчик не подменяет ошибку демонстрационными
числами.

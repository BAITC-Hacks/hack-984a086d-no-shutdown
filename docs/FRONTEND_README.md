# Wind / Agent — интерфейс

Сайт написан на HTML, CSS и JavaScript. График — собственный SVG: не нужны Node.js, сборка, D3, CDN или внешние шрифты. Весь интерфейс загружается с локального сервера API из корня проекта. Порядок установки Python-зависимостей и запуска — в основном README.

Открывайте http://127.0.0.1:8000 после запуска сервера. Открытие `index.html` двойным щелчком показывает оформление, но не соединяется с моделью: браузер должен получить сайт и API с одного origin.

## Файлы

- `index.html` — структура, доступные формы, подписи на русском.
- `styles.css` — тёмно-синяя тема, голубое свечение, адаптивные состояния; поддерживается `prefers-reduced-motion`.
- `app.js` — API, отмена устаревших запросов, проверка сетки прогноза, SVG-график, CSV-экспорт, состояние чата.

## Подключённые API

`GET /api/forecast?turbine_id=T1&as_of_date=2026-02-01&horizon_hours=48&refresh=false`

Ответ: `turbine_id`, `as_of_date`, `origin`, `generated_at`, `horizon_hours`, `power_unit: normalized`, `forecast`, `warning_details`, `model`, `provenance`. Строка прогноза содержит `timestamp`, `predicted_power`, `wind_speed`, `temperature`; опционально `lower`, `upper`.

`GET /api/status` — `model` с метаданными обучения и метриками; `chat.mode` для фактического режима ассистента.

`POST /api/chat` — JSON `{message, turbine_id, as_of_date, horizon_hours, history}`. История состоит из `{role, content}`. Ответ `{reply, mode, actions?}`. Текст выводится через `textContent`, HTML модели не исполняется. Режим local явно подписан: это аналитический помощник с правилами, а не LLM. LLM показывается только когда backend возвращает соответствующий mode.

## Поведение

- Турбина, дата и горизонт 24/48 часов меняют запрос и весь прогноз.
- Пересчёт отправляет `refresh=true`. Ошибки сети, модели и погодного архива показываются явно; мок-данные не подставляются.
- При смене выбора прежний запрос отменяется, старый прогноз удаляется. В интерфейсе не смешиваются выбранная дата и старые значения.
- Дата среза задаёт 00:00 Asia/Almaty. Времена на графике отображаются в том же часовом поясе. Фактическую применимость этого допущения необходимо подтвердить.
- Мощность и ошибки модели остаются в нормализованных единицах. Фронт не считает МВт или МВт·ч без подтверждённого обратного преобразования.
- Условный интервал отображается только при наличии валидных `lower`/`upper`; он не включает погодную неопределённость.
- Если API не подтверждает `as_of_verified: true`, интерфейс явно сообщает, что историческая доступность выпуска не подтверждена. Наличие вычисленного прогноза не объявляется доказательством отсутствия утечки.
- Метрики holdout описывают историческую модель при измеренной погоде. Они не подписываются как точность февральского прогноза.
- CSV скачивается для выбранной турбины и текущего горизонта; отметки времени — UTC.
- Выбор турбины, даты и горизонта сохраняется локально; чат хранится только в памяти вкладки. Кнопка «+» очищает диалог и отменяет текущий запрос чата.

## Настройка внешнего вида

Основные цвета в `:root` файла `styles.css`: `--bg`, `--panel`, `--cyan`, `--blue`, `--muted`. Размеры адаптируются на 1200, 1000, 800 и 580 px. Декоративная турбина, иконки, светящиеся рамки и фон сделаны локальными SVG/CSS, чтобы демонстрация не зависела от внешних ресурсов.

## Обновление интерфейса v3

Верхняя часть страницы использует фотографию `assets/wind-night.jpg` с полупрозрачными градиентами. `assets/energy-grid.jpg` оформляет раздел модели, `assets/operator.jpg` — карточку диспетчерской аналитики. Это иллюстрации; они не обозначают подтверждённые фотографии именно этих турбин. Шрифты системные с поддержкой кириллицы; внешних загрузок нет.

Появились два явно разделённых режима:

- **Февраль / backtest**: `GET /api/forecast?mode=backtest&turbine_id=T1&as_of_date=2026-02-01&horizon_hours=48`. Дата задаётся пользователем. Сохраняется предупреждение о неподтверждённой доступности архивного погодного выпуска.
- **Сейчас / live**: `GET /api/forecast?mode=live&turbine_id=T1&horizon_hours=48`. Историческая дата не отправляется; поле даты недоступно для редактирования. API возвращает фактические `origin` и `as_of_date`. Показываются время получения погоды и свежесть кэша. Историческое ограничение доступности не применяется как утверждение о live-данных.

Чат получает `mode` вместе с выбором турбины и горизонта; `as_of_date` передаётся только в backtest. Быстрые вопросы сравнивают две турбины, ищут лучшее трёхчасовое окно, сравнивают первые и вторые сутки, находят скачок мощности и проверяют данные.

При недоступном `/api/status` интерфейс повторяет запрос один раз, затем показывает кнопку ручного повтора. В сохранённом автономном просмотре `capabilities.live: false` явно отключает live; отсутствие этого поля само по себе не запрещает режим. Полные сведения об источнике, ограничения и метаданные расчёта доступны в раскрывающихся блоках.

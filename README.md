# Wind Dispatch

Рабочий статический фронтенд: HTML + CSS + JavaScript, график на D3.js.
Данные синтетические; сервер и ML-модель не подключены.

## Как открыть в VS Code

1. Распакуйте `wind-dashboard.zip`.
2. В VS Code выберите **File → Open Folder** и папку `wind-dashboard`.
3. Откройте `index.html` в браузере двойным щелчком через Finder / Проводник.
4. Редактируйте файлы, сохраняйте и обновляйте страницу браузера.

Установка Node.js и `npm install` для этого прототипа не нужны.
Для загрузки D3.js, иконок и шрифтов нужен интернет. Если шрифты недоступны,
используются системные; без D3.js график не отображается.

Альтернатива: в терминале VS Code, открытом в папке проекта, запустите:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

На Windows при установленном Python можно использовать `py -m http.server 8000 --bind 127.0.0.1`.
Затем откройте http://localhost:8000. Остановка сервера: Ctrl+C.

## Где что менять

- `index.html` — разметка, заголовки, подписи и подключение скриптов.
- `styles.css` — цвета, шрифты, размеры, мобильная версия.
- `app.js` — состояния, переключатели, генерация мок-данных и график.
- `genForecast()` в `app.js` — источник мок-прогноза.
- `turbines` в `app.js` — демонстрационные мощности турбин.
- `render()` — сводка, погодные показатели, предупреждения.
- `draw()` — график, подсказки, линии и оси.

## Что работает

Выбор T1/T2, даты с 1 по 28 февраля 2026, график на 24/48 часов,
переключение видимости мощности и ветра, выбор часа ползунком,
подсказки на графике и повторный расчёт.
Выбор сохраняется в localStorage браузера. Кнопка «Пересчитать»
обновляет синтетические входные данные и прогноз, а не запускает ML-агента.

Время — UTC. Мощность — средняя за час в МВт; энергия — сумма этих
значений, умноженных на один час, в МВт·ч. Сводка всегда охватывает 24/48 ч,
независимо от выбранного масштаба графика. Граница 28 февраля ограничивает
дату среза, поэтому прогноз может продолжаться в марте.

## Подключение бэкенда позже

Основные поля ответа соответствуют обсуждённому контракту:
`turbine_id`, `as_of_date`, `generated_at`, `horizon_hours`, `forecast`, `warnings`.
В каждой точке: `timestamp`, `predicted_power`, `wind_speed`, `temperature`.
Дополнительное поле `warning_details` содержит severity/title/message для интерфейса.

Для интеграции нужно заменить вызовы `genForecast()` асинхронным запросом
`GET /api/forecast?turbine_id=...&as_of_date=...`, добавить обработку ошибок
и отмену устаревших запросов. Если API отдаёт только строки `warnings`,
преобразуйте их в `warning_details` перед `render()`.
Также согласуйте единицы мощности, UTC и смысл часового интервала.

Текущий `generated_at` — время создания мок-ответа, `as_of_date` — историческая
дата среза. Надпись в интерфейсе не проверяет утечку будущих данных: это задача pipeline.

## Публикация

Папка содержит готовые статические файлы. Их можно разместить на хостинге
статических сайтов, сохранив `index.html`, `styles.css` и `app.js` рядом.
В рамках этой задачи сайт сохранён локально, публичного адреса нет.
